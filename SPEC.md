# SPEC: Impression Editions Website

**Domain:** impressioneditions.com  
**Goal:** A static website that catalogs IE books with cover art, descriptions, download links, and reading previews — modeled on standardebooks.org.

---

## Architecture

```
GitHub (Impression-Editions org repos)
    ↓
build_catalog.py (Python generator script)
    - Scans all repos in the org
    - Extracts metadata from config.json + content.opf
    - Fetches release download URLs via GitHub API
    - Downloads cover images and HTML previews
    ↓
Hugo content/ + static/ files
    ↓
Hugo build → static HTML
    ↓
Netlify deploy (on git push)
```

**No server, no database, no user accounts.** Pure static site.

---

## Data Sources Per Book

Each IE book repo contains:
- `config.json` — pipeline metadata (title, author, slug, pg_id, book_type, subjects, etc.)
- `src/epub/content.opf` — EPUB metadata (description, subjects, language, sources, dates)
- `images/cover.jpg` — cover image
- `{slug}.html` — single-page HTML preview (generated by pipeline)
- GitHub Release — download assets (EPUB, AZW3, advanced EPUB)

The generator script reads all of these and produces Hugo content files.

## Site Structure (URLs)

### Pages

| URL | Description |
|-----|-------------|
| `/` | Landing page — mission, featured books, latest releases |
| `/ebooks` | Browseable grid — search, sort (newest, title, author), filter by tag/subject |
| `/ebooks/{author-slug}/{title-slug}` | Book detail page |
| `/ebooks/{author-slug}/{title-slug}/read` | HTML preview reader (static HTML served as-is) |
| `/ebooks/{author-slug}` | Author page — all books by this author |
| `/about` | What Impression Editions is, our process, standards |
| `/feeds/atom.xml` | Atom feed of new releases |
| `/feeds/rss.xml` | RSS feed of new releases |
| `/feeds/opds.xml` | OPDS catalog (for ereader apps like KOReader, Marvin) |
| `/opensearch.xml` | OpenSearch descriptor |

### Book Detail Page Contents

Each book page (`/ebooks/{author}/{title}`) contains:
- **Cover image** (thumbnail + full)
- **Title and author** (with author link)
- **Description** (from `se:long-description` in content.opf, fallback to `dc:description`)
- **Download links** (direct GitHub release URLs):
  - Compatible EPUB
  - Advanced EPUB
  - AZW3 (Kindle)
  - KEPUB (if available — skip for now, IE doesn't produce these yet)
- **Read online** link → `/ebooks/{author}/{title}/read`
- **Source code** link → GitHub repo
- **Project Gutenberg source** link
- **Wikipedia link** (if available in metadata)
- **Subjects/tags** (clickable → filter)
- **History** (recent commits from GitHub API, capped at 5)
- **Language** indicator

### Landing Page Contents
- IE logo/branding
- Short mission statement (1-2 paragraphs)
- Featured books (curated or latest 6)
- Link to full catalog
- Link to about page

## build_catalog.py Specification

**Input:** GitHub org `Impression-Editions`  
**Output:** Hugo content files, cover images, HTML previews  
**Auth:** `GITHUB_TOKEN` environment variable (for API rate limits)  
**Caching:** Local `.cache/` directory to avoid re-downloading unchanged repos on every build

### Algorithm

```python
1. Fetch all repos from GitHub org (paginated, 100/page)
2. For each repo:
   a. Fetch config.json → title, author, slug, pg_id, subjects, book_type
   b. Fetch src/epub/content.opf → parse for:
      - dc:description + se:long-description
      - dc:subject list
      - dc:language
      - dc:source (PG URL)
      - dc:date (release date)
   c. Fetch releases → get download URLs for .epub, .azw3, _advanced.epub
   d. Download images/cover.jpg → static/covers/{author}_{title}.jpg
   e. Download {slug}.html → static/previews/{author}_{title}.html
   f. Generate Hugo markdown file:
      content/ebooks/{author-slug}/{title-slug}.md
      with front matter containing all metadata
3. Generate author index pages
4. Generate feeds (atom, rss, opds)
5. Log summary (X books processed, Y skipped, Z errors)
```

### Hugo Front Matter (generated per book)

```yaml
---
title: "Popular Tales from the Norse"

author_slug: "george-webbe-dasent"
slug: "popular-tales-from-the-norse"
date: 2026-06-27T10:00:00Z          # release date or last commit date
lastmod: 2026-06-27T10:00:00Z       # last commit date
weight: 100                          # for sorting
description: "Sir George Webbe Dasent's 1859 collection..."
language: "en"
pg_id: 8933
book_type: "nonfiction"
subjects:
  - "Fairy tales -- Norway"
  - "Folklore -- Norway"

  - "Fairy tales"
  - "Norway"
  - "Nonfiction"

github_repo: "https://github.com/Impression-Editions/george-webbe-dasent-popular-tales-from-the-norse"

```

### Error Handling
- Skip repos without releases (log as warning)
- Skip repos without config.json or content.opf (log as error)
- Continue processing other books if one fails
- Exit non-zero on >10% failure rate (signals a systemic issue)

### Caching Strategy
- `.cache/repos.json` — list of repos + last-modified timestamps
- `.cache/{slug}/` — downloaded files (config.json, content.opf, cover, preview)
- On subsequent runs: skip repos whose `pushed_at` hasn't changed
- `--force` flag to ignore cache (for Netlify full rebuilds)
- Cache is gitignored

- Our own mission text

## Feeds

### Atom Feed (`/feeds/atom.xml`)
- Standard Atom 1.0
- Latest 20 releases
- Per-book entries with download links

### RSS Feed (`/feeds/rss.xml`)
- Standard RSS 2.0
- Same content as Atom

### OPDS Catalog (`/feeds/opds.xml`)
- Open Publication Distribution System 1.1
- Allows ereader apps (KOReader, Aldiko, Marvin) to browse and download
- Per-book acquisition links with MIME types
- This is how SE enables "add catalog" in ereader apps

All three feeds are generated by `build_catalog.py` as static XML files.

## Scale Considerations (Thousands of Books)

- **Build time:** GitHub API calls will be the bottleneck. With caching, only changed repos get re-fetched. At ~2s per repo for full metadata fetch, 1000 books = ~30 min initial build, <2 min incremental.
- **GitHub API limits:** 5000 req/hr authenticated. Each book needs ~5 API calls (repo, config, opf, releases, contents). 1000 books = 5000 calls — within hourly limit for full rebuild, and incremental builds use far fewer.
- **Site size:** 1000 books × ~50KB per page = 50MB HTML. Plus covers (~100KB each) = 100MB images. Netlify handles this fine.
- **Page generation:** Hugo can build 10,000+ pages in seconds. Not a concern.
- **Search:** Hugo's client-side search (Pagefind or Fuse.js) works well up to ~2000 pages. Beyond that, consider Algolia or similar. For MVP, use simple tag/author filtering.
